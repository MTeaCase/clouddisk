# 中国大陆访问：实测结论与三条可行路线

先把话说清楚：**Cloudflare 免费版无法“保证”中国大陆访问**。免费版在中国大陆没有节点，
流量要走香港/日本/新加坡/美西，高峰时段会丢包、断连；部分域名还会被 DNS 污染。能做到
“基本可用”的前提是**用自有域名**，而不是 `*.workers.dev` / `*.pages.dev`。

下面是本项目 2026-11-22 在国内网络（上海）的实测结果，可作为判断依据。

## 1. 实测数据

2026-11-22 上海，本机网络，同一时段：

| 目标 | DNS | 结果 |
| --- | --- | --- |
| `clouddisk-api.xiatianyou53.workers.dev` | `108.160.167.159` | **被污染**，TLS 连接超时，完全不可用 |
| `clouddisk-uv1.pages.dev` | `2606:4700:310c::ac42:2f3b` 等 | 可访问，HTTP 200；单请求 1–7 秒，POST 偶发连接重置 |
| `mteacase.github.io` | `185.199.111.153`（Fastly） | **可用且最快**：首屏 0.9 s、app.js 1.4 s |
| `github.com` | `20.247.166.64` | **被墙**（连接超时），只能用 `api.github.com` 推送 |
| `clouddisk.edgeone.cool`（腾讯全球区） | `119.36.225.67` 等国内 IP | 延迟低，但免费项目默认 **401 私有**，需绑域名/控制台访问链接 |
| `766a7c0d…r2.cloudflarestorage.com`（S3 接口） | Cloudflare 边缘 | 可访问且明显更快 |

同样的 8–40 MiB 文件：

| 通道 | 上传 | 下载 |
| --- | --- | --- |
| 经 Pages 代理 → Worker → R2 | **~60 KB/s**（40 MiB / 11 分钟） | 40 MiB 传输被中断 |
| 浏览器 ⇄ R2 预签名直连 | **2.3 MB/s**（8 MiB / 3.6 秒） | **2.6 MB/s**，浏览器内 12 MiB / 2.7 秒 |

所以本项目最终把**文件字节**改走 R2 直连，只把 JSON 请求留在 pages.dev。
这不是“优化”，是把不可用变成可用：差 20–40 倍。

## 2. 路线 A：绑定自有域名（推荐，成本最低）

只要有一个域名（年费几十元），托管到 Cloudflare 免费套餐即可。作用不是“加速”，
而是**让 DNS 与 SNI 干净**，避开 `workers.dev`/`pages.dev` 被针对性污染的问题；
同时能启用 HTTP/3、Early Hints 等。

步骤：

1. 域名 NS 改到 Cloudflare（免费套餐即可）。
2. Pages 项目 → **Custom domains** → 添加 `disk.example.com`，按提示加 CNAME。
   - 前端与 `/api` 都在这个域名下（Pages Functions 已经代理由同源 `/api/*`）。
3. Worker 不必暴露：Pages Function 是**服务端**去访问 `workers.dev` 的，
   属于 Cloudflare 内部出网，不受中国大陆污染影响。
   （如果你想让 Worker 也有独立域名，可在 Workers → Settings → Domains & Routes 绑
   `api.example.com`，前端 `web/config.js` 里把 `apiBase` 填成它即可。）
4. 验证：
   ```bash
   curl -I https://disk.example.com/          # 200 text/html
   curl https://disk.example.com/api/health   # {"ok":true,...}
   ```
5. 证书与 HTTPS 由 Cloudflare 自动签发，无需操作。

预期效果：可用性显著提升，但**速度仍是出境链路**（香港/日本回源），
白天 1–3 秒首屏、上传 1–3 MB/s 属正常；晚高峰可能更慢。

## 3. 路线 B：Cloudflare 中国网络（唯一能“保证”的方案）

Cloudflare China Network（原“中国网络合作伙伴”，由京东云等落地）会在中国大陆境内部署
节点，需要：

- **企业版合同**（Enterprise），并通过合作伙伴签约；
- **ICP 备案**（域名必须在国内备案）；
- 通常还有最低月消费，量级在数千元/月起，按合同而定。

这条路线适合团队/商业用途。个人盘不建议，除非你已经因为其他业务在用企业版。

## 4. 路线 C：把入口搬到国内（可控性最强）

保留 R2 做存储/备份，前端与 API 放到境内：

- 轻量应用服务器 / 云函数（阿里云 FC、腾讯云 SCF）+ 对象存储（OSS/COS）做 CDN 回源；
- 需要 **ICP 备案**；
- 代价是存储要从 R2 迁到 OSS/COS，或者用服务器中转（R2 出网免费，境内服务器
  拉 R2 再对外服务，带宽费用由境内服务器承担）。

适合对“中国大陆必须稳定、可承诺 SLA”的场景；纯个人使用成本不划算。

## 5. 已做的工程缓解措施

| 措施 | 位置 | 作用 |
| --- | --- | --- |
| 文件字节走 R2 预签名直连 | `worker/src/sigv4.ts`、`web/app.js` 的 `uploadDirect` | 绕过 pages.dev 的中转瓶颈（20–40 倍提速） |
| 单域名（Pages + 同源 `/api` 代理） | `functions/api/[[path]].ts` | JSON 少一次跨域；服务端再转 Worker，不受污染影响 |
| 网络错误 / 5xx 自动重试（2 次退避） | `web/app.js` 的 `fetchWithRetry`、`xhrRequest` | 抵抗偶发连接重置 |
| 16 MiB 分片上传 + 单片重传 | `worker/src/index.ts` 的 `/api/pm/parts` | 大文件失败只重传一片 |
| 直连不可用时自动回退代理通道 | `web/app.js` 的 `uploadOne` | 桶 CORS 未配 / 网络阻断时不至于完全不能上传 |
| Range 下载 + 302 到 R2 | `worker/src/index.ts` 的 `handleFile` | 视频可拖进度，下载走快链路 |
| 无外链字体/图标/JS 依赖 | `web/` | 首屏只拉 4 个本地资源，无第三方 DNS |
| 静态资源 `Cache-Control` + gzip | `web/_headers` | 二次访问更快 |
| 上传前置检查 | `worker/src/store.ts` 的 `assertCanUpload` | 空间不足立刻失败，不浪费流量 |

## 6. 不建议的做法

- 用“优选 IP + hosts”硬指 Cloudflare 节点：经常失效，且移动网络无法改 hosts。
- 把 `workers.dev` 域名套一层国内免费 CDN：多数 CDN 不回源境外且要求备案。
- 把 S3 密钥放进前端做直传：既暴露密钥，又绕不过跨境链路问题。

## 7. 一句话建议

先用**路线 A**（自有域名 + Pages 自定义域），它能把“完全打不开”变成“能用但有延迟”；
如果对稳定性有硬要求（例如工作文件必须随时可取），再评估**路线 B/C**。
